# T5 案例详解 — Encoder-Decoder 序列到序列模型的全景解读

> **定位**：本篇以 T5（Text-to-Text Transfer Transformer）为例，将 Transformers 框架的所有模块串联起来，展示 Encoder-Decoder 序列到序列模型从加载到推理的完整生命周期。T5 是"文本到文本"范式的开创者，其架构设计深刻影响了后续的 BART、mT5、Flan-T5、UL2 等模型。

### 2.2 Config 特殊设计

```mermaid
flowchart TB
    A["T5Config(d_model=512, feed_forward_proj='gated-gelu')"] --> B["__post_init__()"]
    B --> C["num_decoder_layers 默认 = num_layers<br/>（编码器解码器对称）"]
    B --> D["解析 feed_forward_proj<br/>'gated-gelu' → dense_act_fn='gelu_new'<br/>is_gated_act=True"]
    B --> E["scale_decoder_outputs<br/>tie_word_embeddings=False 时为 False<br/>（T5v1.1 不缩放）"]
    B --> F["强制 tie_word_embeddings = True<br/>（T5 始终绑定词嵌入）"]

    D --> G["validate_architecture()<br/>验证 feed_forward_proj 格式<br/>必须是 'relu' 或 'gated-{ACT_FN}'"]
```

**关键设计**：
- `attribute_map` 提供别名：`hidden_size` → `d_model`，`num_hidden_layers` → `num_layers`
- `feed_forward_proj` 字符串编码了 FFN 类型：`"relu"` → `T5DenseActDense`，`"gated-gelu"` → `T5DenseGatedActDense`
- `num_decoder_layers` 默认等于 `num_layers`，但可以不同（如编码器 12 层解码器 6 层）
- `is_encoder_decoder = True` 是 T5 的核心标志，影响 AutoModel 分发和掩码生成

### 3.2 权重绑定的特殊性

T5 的权重绑定是所有模型中最复杂的——**三处共享同一个 Embedding 权重**：

```mermaid
graph TB
    Shared["shared.weight<br/>nn.Embedding(32128, 512)"]

    Enc["encoder.embed_tokens.weight"]
    Dec["decoder.embed_tokens.weight"]
    LM["lm_head.weight<br/>nn.Linear(512, 32128, bias=False)"]

    Shared -->|"tie"| Enc
    Shared -->|"tie"| Dec
    Shared -->|"tie"| LM

    style Shared fill:#ff6f00,color:#fff
    style Enc fill:#1565c0,color:#fff
    style Dec fill:#2e7d32,color:#fff
    style LM fill:#7b1fa2,color:#fff
```

**`_tied_weights_keys`** 声明了绑定关系：
```python
_tied_weights_keys = {
    "lm_head.weight": "shared.weight",
    "encoder.embed_tokens.weight": "shared.weight",
    "decoder.embed_tokens.weight": "shared.weight",
}
```

**`scale_decoder_outputs`**：原始 T5 在 lm_head 前对 decoder 输出乘以 `d_model**-0.5`，T5v1.1 不缩放（因为 `tie_word_embeddings=False` 的配置暗示不缩放）。

**关键差异**：

- 编码器使用双向注意力掩码（`create_bidirectional_mask`）
- 解码器使用因果注意力掩码（`create_causal_mask`）

T5 使用 Pre-Norm（先归一化再计算），与 GPT-2 的 Post-Norm 不同：


### 5.4 T5LayerNorm——RMSNorm 的先驱

T5 使用的是 RMSNorm（Root Mean Square Layer Normalization），而非标准 LayerNorm：

```python
class T5LayerNorm(nn.Module):
    def __init__(self, hidden_size, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))  # 只有缩放，没有偏置
        self.variance_epsilon = eps

    def forward(self, hidden_states):
        variance = hidden_states.to(torch.float32).pow(2).mean(-1, keepdim=True)
        hidden_states = hidden_states * torch.rsqrt(variance + self.variance_epsilon)
        return self.weight * hidden_states
```

**与 LayerNorm 的区别**：不减均值、无偏置参数。这个设计后来被 LLaMA 的 `LlamaRMSNorm` 继承。

## 六、注意力系统运作——相对位置编码

### 6.1 T5 的相对位置偏置

T5 不使用绝对位置编码（如正弦编码）或 RoPE，而是使用**相对位置桶偏置**：

```mermaid
flowchart TB
    Q["Query 位置: [0, 1, 2, 3]"]
    K["Key 位置: [0, 1, 2, 3]"]

    Q --> RP["相对位置矩阵<br/>K - Q"]
    K --> RP

    RP --> Bucket["_relative_position_bucket()<br/>对数分桶"]
    Bucket --> Emb["relative_attention_bias<br/>Embedding(32, num_heads)"]
    Emb --> Bias["position_bias<br/>(1, num_heads, seq_q, seq_k)"]

    Bias --> Scores["scores += position_bias"]

    subgraph "分桶逻辑"
        direction TB
        B1["精确位置: 0~max_exact/2<br/>一对一映射"]
        B2["对数分桶: max_exact/2~num_buckets<br/>log(距离) 映射"]
        B3["超出 max_distance<br/>映射到最大桶"]
    end

    Bucket --> B1
    Bucket --> B2
    Bucket --> B3
```

### 6.2 分桶算法详解

```mermaid
flowchart TB
    RP["relative_position<br/>= key_pos - query_pos"] --> Dir{"双向?"}

    Dir -->|"是 (编码器)"| Bi["前半桶: 正距离<br/>后半桶: 负距离<br/>取绝对值"]
    Dir -->|"否 (解码器)"| Uni["仅负距离有意义<br/>min(rp, 0) 后取反"]

    Bi --> Small{"|rp| < max_exact?"}
    Uni --> Small

    Small -->|"是"| Exact["精确映射<br/>bucket = |rp|"]
    Small -->|"否"| Log["对数映射<br/>bucket = max_exact + log(|rp|/max_exact)<br/>/ log(max_distance/max_exact)<br/>× (num_buckets - max_exact)"]

    Exact --> Result["relative_bucket"]
    Log --> Result
```

**关键参数**：
- `relative_attention_num_buckets = 32`：桶数量
- `relative_attention_max_distance = 128`：最大精确距离
- 只有第 0 层计算 position_bias，后续层复用（`position_bias = layer_outputs[1]`）

### 6.3 编码器 vs 解码器的掩码系统

```mermaid
flowchart TB
    subgraph "编码器掩码"
        EMask["create_bidirectional_mask()<br/>双向注意力<br/>所有位置可互相看到"]
    end

    subgraph "解码器自注意力掩码"
        DMask["create_causal_mask()<br/>因果掩码<br/>只能看到当前及之前位置"]
    end

    subgraph "解码器交叉注意力掩码"
        CMask["create_bidirectional_mask()<br/>双向注意力<br/>解码器可看到编码器所有位置"]

    EMask --> Scores1["encoder_scores += bidirectional_mask"]
    DMask --> Scores2["decoder_self_scores += causal_mask"]
    CMask --> Scores3["decoder_cross_scores += bidirectional_mask"]
```

**V5 变化**：T5 使用新的 `masking_utils.py` 中的 `create_bidirectional_mask` 和 `create_causal_mask`，替代了旧的 `modeling_attn_mask_utils.py`。

## 七、缓存系统——EncoderDecoderCache

### 7.1 双缓存架构

T5 作为 Encoder-Decoder 模型，使用 `EncoderDecoderCache` 管理两种缓存：

```mermaid
graph TB
    EDC["EncoderDecoderCache"]

    EDC --> SelfCache["self_attention_cache<br/>DynamicCache<br/>解码器自注意力 KV"]
    EDC --> CrossCache["cross_attention_cache<br/>DynamicCache<br/>解码器交叉注意力 KV"]

    SelfCache --> SelfLayers["Layer 0: K₀, V₀<br/>Layer 1: K₁, V₁<br/>..."]
    CrossCache --> CrossLayers["Layer 0: K₀, V₀<br/>Layer 1: K₁, V₁<br/>..."]

    EDC --> IsUpdated["is_updated: dict<br/>记录每层交叉注意力<br/>是否已更新"]

    style EDC fill:#ff6f00,color:#fff
    style SelfCache fill:#e8f5e9,stroke:#2e7d32
    style CrossCache fill:#e3f2fd,stroke:#1565c0
```

### 7.2 生成过程中的缓存更新时序

```mermaid
sequenceDiagram
    participant Enc as Encoder
    participant Cross as CrossAttention Cache
    participant Self as SelfAttention Cache
    participant Dec as Decoder

    Note over Enc,Dec: 第一次前向（Prefill）

    Enc->>Enc: 编码完整输入
    Enc->>Cross: 保存编码器 KV 到交叉注意力缓存
    Dec->>Self: 保存解码器自注意力 KV
    Dec->>Cross: 读取编码器 KV（交叉注意力）
    Note over Cross: is_updated[layer_idx] = True

    Note over Enc,Dec: 后续前向（Decode）

    loop 每个新 token
        Dec->>Self: 增量更新自注意力 KV
        Dec->>Cross: 直接复用编码器 KV（is_updated=True）
        Note over Cross: 跳过重复计算！
    end
```

**关键优化**：编码器的 KV 在第一次前向后缓存，后续生成步骤中交叉注意力直接复用，无需重新计算。`is_updated` 字典标记每层是否已更新。

### 7.3 与 Decoder-Only 缓存的对比

| 特性 | Decoder-Only (GPT-2/LLaMA) | Encoder-Decoder (T5) |
|------|---------------------------|----------------------|
| 缓存类型 | `DynamicCache` | `EncoderDecoderCache` |
| 缓存内容 | 自注意力 KV | 自注意力 KV + 交叉注意力 KV |
| 编码器缓存 | 无 | 有（一次性计算，后续复用） |
| 交叉注意力 | 无 | 有（Q=decoder, K/V=encoder） |
| is_updated | 无 | 有（标记交叉注意力是否已更新） |

## 八、generate() 生成全流程

### 8.1 T5 的 Seq2Seq 生成时序

```mermaid
sequenceDiagram
    participant User as 用户
    participant Tok as Tokenizer
    participant Enc as Encoder
    participant Cache as EncoderDecoderCache
    participant Dec as Decoder
    participant LM as lm_head
    participant Sample as 采样器

    User->>Tok: "translate English to French: hello"
    Tok-->>User: input_ids = [13924, 4, 11305, ...]

    User->>Enc: 编码 input_ids
    Enc-->>Cache: 保存编码器 KV 到 cross_attention_cache

    User->>Dec: decoder_input_ids = [0] (pad_token_id = decoder_start_token_id)
    Note over Dec: _shift_right(labels) 生成初始 decoder 输入

    loop 生成循环
        Dec->>Dec: Self-Attention（因果 + 自注意力缓存）
        Dec->>Cache: 读取编码器 KV
        Dec->>Dec: Cross-Attention（Q=decoder, K/V=encoder）
        Dec->>LM: lm_head(hidden * d_model^-0.5)
        LM-->>Sample: logits
        Sample-->>Dec: next_token_id
        Dec->>Cache: 更新自注意力缓存
        Sample->>User: token (流式输出)

        alt next_token == eos_token_id
            Note over User: 生成结束
        end
    end
```

### 8.2 _shift_right——解码器输入的特殊处理

```mermaid
flowchart LR
    Labels["labels<br/>[42, 139, 67, 1]<br/>(bonjour 的 token ids)"] --> Shift["_shift_right()"]
    Shift --> Result["decoder_input_ids<br/>[0, 42, 139, 67]<br/>(pad + 右移)"]

    subgraph "shift 逻辑"
        S1["shifted[0] = decoder_start_token_id (=0, pad)"]
        S2["shifted[1:] = labels[:-1]"]
        S3["将 -100 替换为 pad_token_id"]
    end

    Shift --> S1
    Shift --> S2
    Shift --> S3
```

**设计原理**：训练时 labels 右移一位作为解码器输入，实现 teacher forcing。T5 使用 `pad_token_id`（0）作为 `decoder_start_token_id`。

### 8.3 prepare_inputs_for_generation 的特殊处理

```mermaid
flowchart TB
    Input["generate() 调用 prepare_inputs_for_generation()"] --> Check{"past_key_values 存在?"}

    Check -->|"否（首次）"| First["input_ids = 完整输入<br/>decoder_input_ids = decoder_start_token_id"]
    Check -->|"是（后续）"| Sub["input_ids = None<br/>decoder_input_ids = last_token_only<br/>（只传最新 token）"]

    First --> Enc["encoder_outputs 缓存"]
    Sub --> Cache["past_key_values 复用"]

    Enc --> Forward["完整前向传播"]
    Cache --> Forward
```

## 十一、T5Stack——编码器和解码器的统一抽象

### 11.1 T5Stack 的统一设计

T5 的编码器和解码器共享 `T5Stack` 类，通过 `config.is_decoder` 控制行为：

```mermaid
flowchart TB
    Config["T5Config"] --> Copy1["encoder_config<br/>is_decoder=False<br/>use_cache=False"]
    Config --> Copy2["decoder_config<br/>is_decoder=True<br/>num_layers=num_decoder_layers"]

    Copy1 --> EncStack["T5Stack(encoder_config)<br/>编码器"]
    Copy2 --> DecStack["T5Stack(decoder_config)<br/>解码器"]

    subgraph "T5Stack 统一逻辑"
        direction TB
        Emb["embed_tokens"]
        Blocks["T5Block × num_layers"]
        Norm["final_layer_norm"]
        Drop["dropout"]

        Emb --> Drop --> Blocks --> Norm --> Drop2["dropout"]
    end

    EncStack -->|"create_bidirectional_mask"| BMask["双向掩码"]
    DecStack -->|"create_causal_mask"| CMask["因果掩码"]
    DecStack -->|"EncoderDecoderCache"| Cache["双缓存"]
```

**设计精妙之处**：
- 编码器和解码器使用同一个 `T5Stack` 类，只是 `is_decoder` 不同
- `T5Block` 根据 `is_decoder` 决定是否添加 `T5LayerCrossAttention`
- 第 0 层的 `has_relative_attention_bias=True`，计算位置偏置；后续层复用
- 编码器不使用缓存（`use_cache=False`），解码器使用 `EncoderDecoderCache`
